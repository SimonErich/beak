# Beak on Serverpod 4

A small [Serverpod](https://serverpod.dev) 4.0.3 project with a
[Beak](https://github.com/SimonErich/beak) admin panel. Two tables, `author`
and `book`. Serverpod's email login. One admin app that reads and writes both
tables through Beak's stock API, which runs inside the Serverpod server on
Serverpod's own database. No second server, no second database.

## Run it

You need Dart 3.12.2+ and Flutter 3.44.4+ (Serverpod 4.0.3's floor). Until
Beak's obers_ui pin is published, run `melos run link-obers-ui` once at the
repo root: it points this workspace at the sibling `../obers_ui` checkout.

```console
# 1. In examples/serverpod: resolve the whole workspace.
dart pub get

# 2. Local secrets (git-ignored).
cp bookshop_server/config/passwords.example.yaml bookshop_server/config/passwords.yaml

# 3. Terminal 1: the server, on an embedded Postgres, no Docker.
cd bookshop_server && dart run bin/main.dart --apply-migrations

# 4. Terminal 2: the admin.
cd bookshop_admin && flutter run -d chrome --web-port 8095

# 5. In the admin, choose "Create account". The server log prints the code:
#    "Registration code for you@example.com: <code>".

# 6. Terminal 3: let that account into the panel, then sign in again.
cd bookshop_server && dart run bin/beak_admin.dart grant you@example.com
```

Use `dart run`, not `dart bin/main.dart`: only `dart run` builds the Argon2
native asset the email login needs. `bin/beak_admin.dart revoke <email>` takes
the access away again.

## What it proves

- One endpoint method, `beakAdmin.dispatch`, carries the whole Beak API. A
  mixin puts `requireLogin` and the `beak.admin` scope in front of it, so
  Serverpod answers 401 or 403 before any Beak code runs.
- Beak's policy is deny by default. `beak.admin` opens the tunnel and grants
  nothing; `bookshop.staff` reads and writes authors and books; nobody deletes.
- `book.supplierCostInCents` is a `scope=serverOnly` column. It is not in the
  generated client, not in the Beak model, never in a response and never in a
  stored commit receipt, and a client cannot write it.
- A form save is a graph commit on one Serverpod transaction, replayed by its
  save id without inserting twice. Its receipts live in the Serverpod-owned
  table `beak_commit_receipt`, so `serverpod create-migration` owns the schema.
- worm's adapter contract and Beak's data-source contract pass on Serverpod's
  database through `ServerpodSessionAdapter`.

## What it does not

- Deployment. `bookshop_server/Dockerfile` is the template's; it builds from a
  workspace that does not know the Beak packages under `../../packages`.
- Anything beyond two models: no uploads, no business rules, no graph-only
  models, no outbox, no cookie mode, no drift check against the `.spy.yaml`
  files (a test compares the column names, nothing more).
- The Beak model is written by hand, not generated from the Serverpod one.
- Throughput. Nothing here was measured under load.

## Layout

| Package | What it is |
| --- | --- |
| `bookshop_server` | The Serverpod server: `.spy.yaml` models, the gated `BeakAdminEndpoint`, the Beak engine and its policy, `bin/beak_admin.dart`. |
| `bookshop_client` | Generated by Serverpod. Do not edit. |
| `bookshop_flutter` | The template's Flutter app, unchanged. |
| `bookshop_beak` | Pure Dart. The Beak schema classes `Author` and `Book` and their generated parts, which `beak prepare` writes (with nothing else, in a package on `beak_core` alone). Depends on `beak_core` only, so the server never pulls in Flutter. |
| `bookshop_admin` | Flutter web. `BeakPanel` with two `BeakResource` classes, over `ServerpodBeakHttpClient` and `ServerpodAuthAdapter`. |

## Tests

```console
cd bookshop_server && dart test                # embedded Postgres, no Docker
cd bookshop_admin && flutter test              # widget tests with a fake dispatch
cd bookshop_admin && BOOKSHOP_SERVER_LOG=<server log> flutter test test_live/admin_flow_test.dart
```

The live test needs the server from step 3 running with its output in that
log. It signs up by email (reading the code from the log), grants and revokes
access with `bin/beak_admin.dart`, then creates, edits and filters authors and
books, replays a graph commit and checks the supplier cost never leaves the
server. Give `BOOKSHOP_SERVER_URL` and `BOOKSHOP_SERVER_DIR` when the server is
not on `localhost:8080` next to the admin.

## Changing a model

Edit the `.spy.yaml`, regenerate, migrate, mirror the change in the Beak
schema class, regenerate its parts. `AGENTS.md` has the commands.
