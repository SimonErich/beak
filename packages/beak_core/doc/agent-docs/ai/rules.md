# Rules for agents

> The MUST and NEVER rules for an agent that changes a Beak project, each with the command that checks it, and the open traps that change generated code.

For coding agents. Humans: see [Code guardrails](../contributing/code-guardrails.md). Every rule below has a check you can run. A rule you cannot check is a guess, so run the check before you report a change as done. Commands run from the project root; `melos` commands run in a clone of the Beak repository only.

## Rules

### Interface

| Rule | Check |
| --- | --- |
| NEVER import `package:flutter/material.dart` or `package:flutter/cupertino.dart`. Draw with obers_ui through `package:beak/ui.dart`, charts through `package:beak/charts.dart` | `grep -rn "flutter/material.dart\|flutter/cupertino.dart" lib test` prints nothing. In the Beak repository: `melos run guard-material` |
| MUST write widgets as `HookWidget`. NEVER write a `StatefulWidget` | `grep -rn "extends StatefulWidget" lib` prints nothing. In the Beak repository: `melos run guard-hooks` |
| NEVER add `obers_ui`, `obers_ui_autoforms` or `obers_ui_charts` to your `pubspec.yaml` with a version or ref of your own. `beak` pins all three to one commit | `flutter pub get` resolves, and `pubspec.yaml` has no `obers_ui` entry |
| NEVER build a second router or dependency scope around `BeakPanel`. Beak wires signals, GetIt and go_router itself. Reach the panel's services with `beakDependencies(context)` | `dart analyze` |
| MUST import the library that matches the file: `package:beak/panel.dart` in panel code, `package:beak/server.dart` in `lib/server.dart` and server-side domain code, `package:beak/migrations.dart` in migrations and seeders. NEVER import `server.dart` or `migrations.dart` from a file the panel reaches | `beak doctor` reports `no panel file imports the server` |

### Types

| Rule | Check |
| --- | --- |
| MUST reference fields through the generated model: `ProductModel.name`. NEVER write a column name as a string, and NEVER use the `.key` or `.column` of a field where a field is accepted | `grep -rn "Columns\.\|\.column\b" lib` prints nothing in screens and resources |
| NEVER use `dynamic`, `as` casts or `Map<String, dynamic>` as a domain type. Use `BeakRecord`, `BeakValue`, `BeakQuerySpec`, enums and typed classes. Mark unavoidable interop with `// interop:` | `dart analyze` (the scaffold turns on `strict-casts`, `strict-inference`, `strict-raw-types`), then `grep -rnE "\bdynamic\b" lib` |
| MUST name a number with its unit: `maxSizeInBytes`, `timeoutInSeconds`, `headerGapInPixels`. NEVER add a bare `width`, `size` or `timeout` | Review the diff for numeric names without `In<Unit>` |
| MUST pass a `BeakModelAction` object where an action is expected, and a field where a field is expected. NEVER pass the action name or column key as a string | `dart analyze` |
| MUST declare a known value set as an enum or sealed class with `@EnumLabels` and `@Badges`. NEVER compare against a string literal | Review the diff |
| MUST store money as a `BeakDecimal` with `semantic: BeakSemantic.money(currency: 'EUR')`. NEVER use `double` for an amount | `beak prepare` accepts the class; the model test asserts an exact sum |

### Generated files

| Rule | Check |
| --- | --- |
| NEVER edit `*.beak.dart`, `lib/beak/*.g.dart`, or a `lib/main.dart`, `bin/serve.dart` or `bin/migrate.dart` that starts with the `GENERATED BY` header. Change the schema class, the resource class, the screen or `beak.yaml` instead | `beak doctor` reports `generated files up to date` |
| MUST run `beak prepare` after you edit a schema class, a `BeakResource`, a `BeakScreen` or `beak.yaml`. `beak doctor` also fails on a schema error, but only `beak prepare` writes the code | `beak prepare` prints `generated  up to date` on the second run |
| MUST add a new `BeakResource` to `resources: [...]` in an authored `lib/main.dart`. A generated `lib/main.dart` finds it by itself | `beak doctor` warns and names the class when an authored `lib/main.dart` omits one |
| MUST put files where the layout says: schema `lib/resources/<plural>/models/<name>.dart`, resource `lib/resources/<plural>/<name>_resource.dart`, screens `lib/resources/<plural>/screens/`, custom pages `lib/screens/`, migrations `lib/migrations/` | `beak prepare` discovers the class; `beak make:resource Name` shows the layout |
| MUST say which bootstrap a change assumes. Generated is `runApp(const BeakApp())`, authored is `BeakPanel(resources: [...])` | `head -5 lib/main.dart` shows the `GENERATED BY` header or not |

### Data and migrations

| Rule | Check |
| --- | --- |
| NEVER edit a migration that already ran. Add a new one | `beak migrate status` lists what ran |
| MUST change a shipped table with `beak make:migration <Name> --from-drift`, read the file, then `beak migrate`. A new field in Dart alone does not change the database | `beak doctor` reports no column a class declares that the table lacks |
| NEVER apply migrations from server start-up code, and NEVER run `beak migrate fresh` or `refresh` against a database with data you need. `beak migrate` applies migrations; the one exception is `DATABASE_URL=sqlite::memory:`, where the host applies them so the database has tables | `beak migrate status` before and after |
| MUST request relations explicitly with a `BeakRelationLoad` in the `BeakQuerySpec`. Beak never lazy-loads: a relation appears on a record only when the spec asked for it | The query count of a list page in a `BeakRecordingDataSource` test |
| NEVER touch a table that another system migrates. Mark it `@Resource(managesSchema: false)` (`beak introspect --ownership external`) | `beak prepare` writes no create-table migration for it |
| MUST use worm types only in `lib/migrations/`, `lib/seeders/` and code that imports `package:beak/migrations.dart`. NEVER put a worm type in a schema class, a resource or a screen | `beak doctor` reports `no panel file imports the server` |

### Server and security

| Rule | Check |
| --- | --- |
| MUST put a business rule on the schema class (`validationRules`, `behavior`, `BeakExists` with `BeakFieldMatch`). The server re-runs it on every save. NEVER put it only in a widget callback | An API test that posts the invalid write and expects a rejected receipt |
| NEVER treat `canCreate`, `canEdit`, `canDelete`, `hidden` or a hidden navigation entry as security. They hide UI. Who may do what is decided by `BeakPolicies`, `BeakModelRules` and `BeakAccess` in `lib/server.dart` | A per-role API test that expects `401` or `403` |
| NEVER ship a `BeakServer` without a `policy`. Without one it allows everything to everyone, and warns once at boot only when bound beyond loopback | `grep -n "policy:" lib/server.dart` |
| MUST route writes of a `graphOnly` model through `POST /api/commits`. NEVER add a per-record `PATCH` or `DELETE` call for it | `flutter test` on the form; the per-record route answers `422` |
| MUST keep secrets in `.env`, which is git-ignored, and NEVER commit one. Commit `.env.example` | `git status` shows no `.env` |
| NEVER start `serverpod start` (interactive) or leave a `beak dev` process behind. Ask the person to run a long-running server | The terminal has no process the task started |

### Working process

| Rule | Check |
| --- | --- |
| MUST read the corrections table on the [AI directory](index.md), then the row of the [Task map](task-map.md) for the task, then open the file that row names. Copy its shape | The change follows the named file |
| MUST search the project and the examples before adding a widget, mapper or helper. Extend, do not fork | `grep -rn "<name>" lib ../examples` shows no near copy |
| MUST write the failing test first, then the code. Use `InMemoryBeakDataSource` for panel tests, the real host on `sqlite::memory:` for server tests | The test fails before the change and passes after |
| MUST treat the source as the truth when a docs page disagrees, and report the mismatch | The report names the page and the file |
| MUST show command output before you say a task is done. Done means `beak doctor`, `dart format .`, `flutter analyze` and `flutter test` are clean | The four outputs |
| NEVER commit unless asked, and NEVER edit `CLAUDE.md`, `AGENTS.md` outside your task, or the block between the markers | `git diff --stat` |

## Known traps

These are open in 0.9.0. Each changes what you should generate. A row says what happens, what to write instead, and where the page is. When one is fixed, the row goes.

| Trap | What happens | Generate instead | Read |
| --- | --- | --- | --- |
| A page is at most 200 rows | The server answers a request for `perPage: 1000` with 200 rows and an envelope whose `perPage` says 200, while `total` still counts every match. A screen that assumes it got them all shows a partial list without an error. A panel list rejects a page size above 200 | Ask for 200 or fewer. Page with `page * perPage < total`, or take totals from `model.summary(...)` or an aggregate | [Queries](../reference/queries.md) |
| `%`, `_` and `\` in a search term are literal | `contains`, `startsWith`, `endsWith` and the search escape all three, so `50%` finds `50%` and not every row that holds `50`. In a hand-written `like` or `ilike` operand a backslash is the escape character on every database, so a literal backslash is `\\` | Never build a pattern by hand from user input. Use `contains`, or `beakEscapeLike(term)` for the part you did not write | [Queries](../reference/queries.md) |
| Serial-key creates and enum writes are untested on Postgres | A serial integer key round-trips on SQLite, and a native Postgres enum reads as text. A create that relies on `RETURNING` for a serial key, and a write of a label into an enum column, have no test against a real Postgres | Declare the key as `int? id`, as `beak introspect` does, not as a string. Try a create and an enum write against the real database before you ship the form | [An existing database](../start-here/paths/existing-database.md) |
| Saves over a custom data source are staged | `POST /api/commits` works over any `BeakDataSource`, but it is not atomic: operations run one by one in dependency order and stop at the first failure, with no rollback. An operation with `expectedUpdatedAt` is refused, receipts live in memory (the newest 1024), so a restart forgets them, and a model with `behavior` or a `preparePlan` makes boot throw unless the source is a worm source | Keep `WormDataSource` on a transactional adapter for behavior, business rules and version checks. Expect a half-applied save over anything else, and read the receipt | [Custom data sources](../extending/custom-data-sources.md) |
| `hidden: true` in `beak.yaml` removes the whole resource | Not only the sidebar entry: the route answers `404`, and a hidden model that nothing relates to is unknown to the panel | To hide from the sidebar, leave the model out of `resources: [...]` in an authored `lib/main.dart`. Relate the model to a visible one if a form must edit it | [Hide a resource](../recipes/hide-a-resource.md) |
| The panel does not compile against the pinned obers_ui | `beak_frontend` uses many obers_ui APIs the pinned commit lacks (175 analyzer errors across 14 files, among them `OiPageLayout`, `OiFilterChip`, `OiCapacityIndicator` and `OiIcon.raw`), so `flutter test` and `flutter run` fail to compile the panel. The API half (`beak migrate`, `beak dev`) is unaffected | Write a `pubspec_overrides.yaml` that points the three obers_ui packages at a local checkout, until the pin moves | [Installation](../start-here/installation.md) |
| The `v0.9.0` tag does not exist yet | A plain `beak create` writes `ref: v0.9.0` and `flutter pub get` fails | `beak create <name> --beak-path <absolute repo root>` or `--beak-ref <branch>` | [Installation](../start-here/installation.md) |
| `BeakWizardScreen` forwards 26 of the 29 `BeakFormScreen` parameters | `layout`, `recordHeader` and `editingLabel` do not exist on it, because they only mean something on a single page | `BeakFormScreen(steps: [...])` when you need one of them | [Multi-step forms](../forms/multi-step-forms.md) |
| `searchable: true` on a custom column | Typing a search term is refused with a `422` (`BeakValidationException`: `Column "..." does not support automatic search.`) | Leave `searchable` off a `BeakCustomColumn` | [Custom columns](../extending/custom-columns.md) |
| The API has no rate limit | A caller can send requests as fast as the host accepts them | Limit at the proxy or in middleware | [Security](../shipping/security.md) |

## Done means

A change is done when all of these are true, and you have shown the output:

1. `beak prepare` runs clean and a second run says `up to date`.
2. `beak doctor` ends with `All checks passed.` and no new `WARN`.
3. `dart format .` changes nothing, and `flutter analyze` reports no issues.
4. `flutter test` passes, and it includes a test that fails without your change.
5. `beak agents --check` exits `0` when you touched anything an agent reads.
6. For a server-side change, a test hit the real host and asserted the rejection, not only the success.
