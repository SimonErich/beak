Now you give the journal something to store. This part defines the `Bird` model, creates the `birds` table with a migration, and saves and reads back your first bird.

## Goal

A `Bird` model backed by a real `birds` table, plus a script that logs a bird and reads it straight back out.

## Scaffold a model

Ask worm for a starting point:

```bash
dart run worm:worm make:model Bird
```

```text
created  lib/models/bird.dart
```

Open the file. The skeleton is deliberately minimal:

```dart title="lib/models/bird.dart (generated skeleton)"
import 'package:worm/worm.dart';

/// Generated by `worm make:model`.
@Table(name: 'birds')
final class Bird extends Model {
  /// Default constructor.
  Bird();

  /// Primary key.
  late final String id;
}
```

This does not compile yet, and that is on purpose. `Model` asks every subclass for an `id`, a `toRow()`, and a way to hydrate rows back into objects. The skeleton hands you the annotation and the class shape. You fill in the rest.

## Flesh out the model

Replace the file with the full model. It stores its columns in worm's attribute store and exposes typed getters over them:

```dart title="lib/models/bird.dart"
import 'package:worm/worm.dart';

import '../ids.dart';

/// A bird we keep an eye on.
@Table(name: 'birds')
final class Bird extends Model {
  /// Logs a new bird with a fresh id.
  Bird({required String name, required String species}) {
    setAttribute('id', newId());
    setAttribute('name', name);
    setAttribute('species', species);
  }

  Bird._();

  /// Hydrates a [Bird] from a database row.
  factory Bird.fromRow(Map<String, Object?> row) {
    final bird = Bird._();
    row.forEach(bird.hydrateAttribute);
    return bird..markPersisted();
  }

  @override
  String get tableName => Bird$.tableName;

  @override
  Object get id => getAttribute('id') ?? '';

  /// The nickname we gave this individual.
  String get name => switch (getAttribute('name')) {
    final String value => value,
    _ => '',
  };

  /// Common species name.
  String get species => switch (getAttribute('species')) {
    final String value => value,
    _ => '',
  };

  @override
  Map<String, Object?> toRow() => <String, Object?>{
    'id': id,
    'name': name,
    'species': species,
  };

  /// Starts a typed query against the `birds` table.
  static QueryBuilder<Bird> query() => QueryBuilder<Bird>.from(
    QueryContext<Bird>(
      adapter: Worm.adapter(),
      table: Bird$.tableName,
      hydrate: Bird.fromRow,
    ),
  );
}

/// Typed column references for [Bird] queries.
abstract final class Bird$ {
  /// The table backing [Bird].
  static const String tableName = 'birds';

  /// The `name` column.
  static const StringField name = StringField('name');

  /// The `species` column.
  static const StringField species = StringField('species');
}
```

Three pieces are worth naming:

- The **attribute store**. `setAttribute` / `getAttribute` / `hydrateAttribute` hold the row's columns. Your getters pattern-match those values into real types, with no `as` casts.
- The **`tableName` override**. The `@Table(name: 'birds')` annotation is read by code generation only. At runtime, worm resolves the table through this override. Leave it off and `save()` throws a `ConfigurationException`.
- The **companion class `Bird$`**. It holds typed field constants like `Bird$.name`. You write queries against these, so a misspelled column is a compile error. This is your first contact with the `Model$` pattern that runs through the whole ORM.

:::note
Worm can generate `Bird$`, `fromRow`, and `query()` for you with `dart run worm:worm gen`. This tutorial hand-writes them so every line is visible and the project runs with no build step. See [Code generation](../models/code-generation.md) for the generated path.
:::

## Create the table

Scaffold a migration:

```bash
dart run worm:worm make:migration create_birds_table --table birds
```

Edit the generated file to describe the columns:

```dart title="migrations/20260702_094946_create_birds_table.dart"
import 'package:worm/worm.dart';

/// Generated by `worm make:migration`.
final class CreateBirdsTable extends Migration {
  /// Default constructor.
  const CreateBirdsTable();

  @override
  String get name => '20260702_094946_create_birds_table';

  @override
  Future<void> upSchema(Schema schema) async {
    await schema.create('birds', (table) {
      table.idUuid();
      table.string('name');
      table.string('species');
      table.timestamps();
    });
  }

  @override
  Future<void> downSchema(Schema schema) async {
    await schema.drop('birds', ifExists: true);
  }
}
```

`table.idUuid()` gives you a string primary key column named `id`. `table.timestamps()` adds nullable `created_at` and `updated_at`, which worm fills on every save. Your migration filename carries a timestamp, so yours will differ from the one above.

## Register the migration

A migration only runs once your CLI knows about it. Import it and add it to the list in `bin/nestwatch.dart`:

```dart title="bin/nestwatch.dart"
import 'dart:io';

import 'package:nestwatch/nestwatch.dart';
import 'package:worm/worm.dart';

import '../migrations/20260702_094946_create_birds_table.dart';

Future<void> main(List<String> args) async {
  final adapter = await bootNestwatch();
  final context = CliContext(
    out: stdout,
    err: stderr,
    projectRoot: Directory.current,
    environment: Worm.environment,
    now: DateTime.now,
    adapterFactory: () => adapter,
    migrations: const <Migration>[CreateBirdsTable()],
    seeders: const <Seeder>[],
  );
  final code = await WormCommandRunner(context).run(args) ?? 0;
  if (code != 0) exit(code);
}
```

Run it:

```bash
dart run nestwatch migrate
```

```text
migrated  20260702_094946_create_birds_table
```

## Save and read a bird

Write a small script that logs a bird, reads it back by id, and counts the table:

```dart title="bin/log_bird.dart"
import 'package:nestwatch/models/bird.dart';
import 'package:nestwatch/nestwatch.dart';

Future<void> main() async {
  await bootNestwatch();

  final robin = Bird(name: 'Rosie', species: 'Robin');
  await robin.save();
  print('Logged ${robin.name} the ${robin.species}.');

  final found = await Bird.query().findOrFail(robin.id);
  print('Read it back: ${found.name} (${found.species}).');

  final total = await Bird.query().count();
  print('Birds on file: $total');
}
```

## Checkpoint

```bash
dart run bin/log_bird.dart
```

```text
Logged Rosie the Robin.
Read it back: Rosie (Robin).
Birds on file: 1
```

## What just happened

`save()` saw a brand-new model and issued an INSERT, stamping `created_at` and `updated_at` for you. `Bird.query()` opened a typed builder, and `findOrFail(robin.id)` looked the row up by primary key and hydrated it back into a `Bird` through `Bird.fromRow`. `count()` pushed a `COUNT(*)` down to SQLite rather than loading rows. Every column you touched went through a typed `Bird$` field or a typed getter.
