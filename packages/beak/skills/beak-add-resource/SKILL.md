# Add a resource

A resource is a schema class (the data) plus a `BeakResource` (how the panel
shows it). Beak derives the model, the REST API, the create-table migration and
both sides of every relationship from the schema class.

Read first, by path: `.dart_tool/beak/docs/ai-index.md`,
`.dart_tool/beak/docs/models/defining-models.md` and
`.dart_tool/beak/docs/recipes/add-a-resource.md`. To search them run
`grep -rn "<term>" .dart_tool/beak/docs` (ignore-aware search tools skip
`.dart_tool/`). Folder missing? Run `beak docs`.

## Steps

1. Confirm the project: `pubspec.yaml` depends on `beak`. If it depends on
   `beak_serverpod_flutter`, stop and use `beak-serverpod-setup`. If the table
   already exists in a database, use `beak-adopt-database`.
2. Scaffold with `beak make:resource <Name> --fields name:string!,email:string,active:bool!`.
   Kinds: `string`, `text`, `int`, `decimal` (an exact `BeakDecimal`), `double`,
   `bool`, `datetime`. A trailing `!`
   means required; without it the field is nullable (`bool` becomes a tri-state
   `bool?`). It writes `lib/resources/<plural>/models/<snake>.dart` and
   `lib/resources/<plural>/<snake>_resource.dart`, then runs `beak prepare`. It
   refuses to overwrite either file.
3. Finish the schema class by hand (relations and enums are not scaffolded):
   - Exactly one `@Display()` on the field that names a record in pickers,
     links and titles (`beak prepare` rejects a second).
   - The Dart type picks the column, nullability picks required. Bounds are
     rules: `@Column(rules: [BeakMaxLength(120)])`. Search, sorting and
     filtering are switched on per column:
     `@Column(searchable: true, sortable: true, filterable: true)`.
   - Relations are fields typed by another schema class, with that file
     imported: `@BelongsTo(inverse: false) late final Company? company;`,
     `@HasMany(owned: true, onDelete: BeakOnDelete.cascade) late final List<Line> lines;`
     for children saved with their parent, `@BelongsToMany()` for many-to-many.
   - Never write a column or table name as a string. Never edit `*.beak.dart`
     or `lib/beak/*.g.dart`.
4. Do step 3 before the first `beak migrate`. `create_<plural>_table.dart`
   reads the model when it runs, so it follows the schema until some database
   has applied it. After that, a change is `beak-evolve-schema`'s job.
5. Run `beak prepare` and fix every issue it lists. Then open the generated
   `<snake>.beak.dart` next to the schema and use only the statics it declares
   (`SupplierModel.name`, `SupplierModel.company.name`).
6. Edit `<snake>_resource.dart`: title, `BeakIconToken(OiIcons.<name>)`,
   `navigationGroup`, `filters:` and `screens: [BeakTableScreen(...),
   BeakFormScreen(...)]`. Every reference is a generated field, for example
   `SupplierModel.name.textFilter()` or `SupplierModel.company.inputCombobox()`.
   Copy the shape from `references/resource-example.md`.
7. Register it. Open `lib/main.dart`, or the file `panel.entrypoint` names in
   `beak.yaml`. If it starts with the header "GENERATED BY beak prepare", the
   panel is generated and picks up every `BeakResource` class under `lib/`:
   register nothing (icon and section can also live under `resources:` in
   `beak.yaml`). Otherwise it is authored: add `SupplierResource()` and its
   import to `BeakPanel(resources: [...])`; `make:resource` printed the lines.
8. Apply it with `beak migrate`, which runs `beak prepare` and then the
   generated `bin/migrate.dart`. A failing migration prints its error in your
   terminal and the command exits non-zero; `beak migrate status` shows what is
   applied and what is pending.
9. Test it (see below), then run the gate.

## Test

Put a widget test in `test/` that boots the panel over an in-memory source and
opens the new section:

```dart
final source = InMemoryBeakDataSource(registry: buildBeakRegistry())
  ..seed(const SupplierModel(), [
    beakFakeRecord(
      const SupplierModel(),
      overrides: {SupplierModel.name.key: SupplierModel.name.encode('Acme')},
    ),
  ]);
await tester.pumpWidget(BeakApp(dataSource: source)); // authored: BeakPanel(resources: [SupplierResource()], dataSource: source)
await tester.pumpAndSettle();
await tester.tap(find.text('Suppliers').first);
await tester.pumpAndSettle();
expect(find.text('Acme'), findsOneWidget);
```

Imports: `package:beak/testing.dart`, `package:flutter/widgets.dart`,
`package:flutter_test/flutter_test.dart`, and the project's
`beak/app.g.dart` and `beak/registry.g.dart`. `beakFakeRecord` fills every
column, primary key included. Set a wide surface with
`tester.binding.setSurfaceSize` when a table is under test.

## Gate

`beak doctor` (all checks pass, the database matches the schema classes),
`dart format .`, `flutter analyze` and `flutter test` are clean.

## Example prompt

```text
Use the beak-add-resource skill to add a Supplier resource (name required, email, phone, active) that belongs to Company, with a searchable table, an active filter and a two-card form.
```
