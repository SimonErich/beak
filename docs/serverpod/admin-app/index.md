# Admin app in your workspace

This section covers one setup: a Serverpod 4 workspace gains an admin app, and Beak's API runs inside the Serverpod server behind one gated endpoint, on Serverpod's own database. You keep Serverpod's tables, migrations and sign-in. It is a proof of that idea, built and tested on one example (`examples/serverpod`), so the section documents its limits as carefully as its steps.

## What the workspace looks like

The example is a Serverpod project called `bookshop`, with two tables, `author` and `book`. Two packages are new, the other three come from `serverpod create`.

| Package | What it is | You edit it |
| --- | --- | --- |
| `bookshop_server` | The Serverpod server: `.spy.yaml` models, and under `lib/src/beak/` the endpoint, the engine, the policy and the scopes | Yes |
| `bookshop_client` | Generated by Serverpod, now with `client.beakAdmin.dispatch` | Never |
| `bookshop_flutter` | The template's Flutter app, untouched | No |
| `bookshop_beak` | New. Pure Dart: one Beak schema class per table, mirroring the `.spy.yaml` models, plus the parts `beak prepare` writes | The schema classes and the barrel |
| `bookshop_admin` | New. Flutter web: a `BeakPanel` with one `BeakResource` per table | Yes |

`bookshop_beak` depends on `beak_core` only, so the server can import it without pulling in Flutter, and the admin app shares the same classes.

## What it proves

- One endpoint method, `beakAdmin.dispatch`, carries the whole Beak API. `requireLogin` and the `beak.admin` scope sit in front of it, so Serverpod answers 401 or 403 before any Beak code runs.
- Beak's policy is deny by default. `beak.admin` opens the tunnel and grants nothing; a second scope, `bookshop.staff`, reads and writes authors and books; nobody deletes.
- A server-only column, `book.supplierCostInCents`, never leaves the database: not in the generated client, not in the Beak model, not in a response, an export or a stored receipt, and a client cannot write it.
- A form save is a graph commit on one Serverpod transaction, replayed by its save id without inserting twice. Its receipts live in a table Serverpod's migrations own.
